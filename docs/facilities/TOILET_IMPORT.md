# 공중화장실 수집 실행 안내

`toilet_import.py`는 행정안전부 공중화장실 v2 API에서 지정한 자치단체의 전체 목록을 받아 시설 저장소에 반영한다. Python 3.10 이상, 표준 라이브러리만 사용한다. 가상 응답 테스트와 실제 수원시 인증 호출·저장을 검증했다(2026-11-12 한국 시간).

## 1. 인증키 발급

1. [공공데이터포털의 공중화장실정보 조회서비스](https://www.data.go.kr/data/15155058/openapi.do)에 로그인한다.
2. 해당 서비스의 **활용신청**에서 개발 목적과 필요한 항목을 작성해 신청한다. 승인 상태와 허용 호출량을 확인한다. 기존 공공데이터 키가 있어도 이 서비스의 이용 권한을 확인한다.
3. 마이페이지의 데이터활용/Open API 활용 내역에서 해당 서비스를 열고 **일반 인증키(Decoding)**를 확인한다. 포털 메뉴 이름은 변경될 수 있다.
4. 서버에는 Decoding 값을 설정한다. 수집기가 URL 인코딩을 한 번 수행하므로 Encoding 값을 넣으면 이중 인코딩으로 인증이 실패할 수 있다.

인증키는 사용자가 직접 발급·설정했다. 키를 사용한 공식 API 호출이 정상 작동하는 것을 확인했다. 키를 채팅, 커밋, PR 또는 실행 명령 인자로 전달하지 않는다.

## 2. 로컬 설정

프로젝트 루트의 `.env`에 아래 한 줄을 추가하고 값 부분만 본인의 Decoding 키로 바꾼다. 기존 카카오 키 등 다른 설정은 유지한다. `.env.example`에는 실제 키를 넣지 않는다.

```dotenv
PUBLIC_DATA_SERVICE_KEY=여기에_Decoding_인증키
```

`.env`는 Git 제외 대상이다. 새 환경에서 `.env`가 없으면 `.env.example`을 복사해 만들 수 있다. 이 수집기는 `PUBLIC_DATA_SERVICE_KEY` 한 항목만 읽으며, 운영체제 환경 변수 값이 있으면 `.env`보다 우선한다. 환경 변수가 빈 값으로 설정되어 있어도 파일 값으로 대체하지 않고 오류를 낸다.

파일에 저장하지 않고 현재 PowerShell 세션에서만 사용하려면 다음처럼 입력할 수 있다. 입력 내용은 화면과 명령 기록에 나타나지 않는다.

```powershell
$facilityKeyInput = Read-Host '공공데이터 Decoding 키' -AsSecureString
$env:PUBLIC_DATA_SERVICE_KEY = [System.Net.NetworkCredential]::new('', $facilityKeyInput).Password
$facilityKeyInput.Dispose()
Remove-Variable facilityKeyInput
```

작업 후 세션 변수를 없애려면 `Remove-Item Env:PUBLIC_DATA_SERVICE_KEY`를 실행한다. 수집기에 필요한 키이며 기존 경로 API의 Bearer 토큰과 다르다.

## 3. 수원시 코드 확인과 사전 검증

서비스 상세 페이지의 참고문서·연계정보 안내를 통해 공식 **개방자치단체코드** 자료를 확인하고 수원시의 정확한 값을 선택한다. 행정구역 코드나 시군구 코드를 비슷하다는 이유로 대신 넣지 않는다. 2026-11-12 공식 API에 수원시 도로명주소 조건으로 조회하여 `OPN_ATMY_GRP_CD=3740000`을 확인했다. 수원시는 `3740000`을 사용한다.

다음 수원시 명령은 프로젝트 루트에서 실행한다. 다른 지역은 공식 코드값을 확인해 교체한다.

```powershell
python toilet_import.py --region-code 3740000 --dry-run
```

`--dry-run`도 실제 API를 호출해 쿼터를 사용하지만 시설 DB는 생성·변경하지 않는다. 출력의 `status: validated`, `expected`, `received`, `pages`, `missing_address`를 확인한다. 0건이면 코드와 권한을 먼저 점검한다. 인증·페이지 구조가 실제 제공 내용과 다르면 오류로 멈추며, 검증을 무시하고 저장하지 않는다.

검증 후 같은 지역을 저장한다.

```powershell
python toilet_import.py --region-code 3740000
```

기본 페이지 크기는 100, 최대 페이지 수는 100이다. 기본 예산은 최대 10,000개 레코드이며, 실제 API 요청은 일시 오류에 대해 페이지마다 최대 3회까지 발생할 수 있다. 전체 건수가 예산을 넘으면 저장하지 않는다. 필요 시 승인 쿼터를 확인하고 `--max-pages`를 조절한다(1~1000). `--page-size`는 1~100이다. 전국 자동 수집은 제공하지 않는다.

설정 파일과 DB 경로는 `--env-file`, `--database`로 지정할 수 있다. 다른 경로에 생성한 DB도 직접 Git 제외 여부를 확인한다.

## 4. 저장과 오류 처리

- 확인한 목록 주소: `https://apis.data.go.kr/1741000/public_restroom_info_v2/info_v2`.
- 지역 필터: `cond[OPN_ATMY_GRP_CD::EQ]`. 첫 페이지부터 마지막까지 총건수·페이지 번호·페이지 크기·실제 행 수를 검사한다.
- 응답은 공식 Swagger의 `response.header`와 `response.body.items.item` 구조를 기대한다. 실제 성공 코드는 문자열 `0`으로 확인했다. 파서는 `0`과 기존 `00` 표기를 지원한다. 단일 항목 객체 및 빈 항목 표현을 지원한다.
- 관리번호·지역 코드·시설명 누락, 다른 지역의 행, 중복 식별자, 수집 도중 총건수 변경, 잘못된 숫자 필드는 전체 실행 실패로 처리한다. 임의로 불량 행만 빼고 완료 처리하지 않는다.
- 모든 페이지가 정상일 때만 한 트랜잭션으로 저장한다. 중간 요청 실패 시 기존 데이터에 손대지 않는다. 빈 목록도 기존 시설을 삭제하지 않는다.
- 식별자 기준 갱신으로 내부 ID를 유지한다. 기존 비활성 상태를 보존하고, 주소가 같은 시설은 기존 좌표와 변환 메타데이터를 보존한다. 주소가 바뀌면 좌표를 비우고 `pending`으로 되돌린다.
- 처음 수집한 화장실은 좌표 없는 `pending` 상태다. 주소 변환·지도 표시·삭제 동기화·증분 갱신은 후속 작업이다. `DAT_UPDT_SE`는 원문만 저장하고 아직 삭제 코드로 해석하지 않는다.
- 비상벨·기저귀교환대 여부의 실제 코드값이 미확인이라 이번 버전에서는 `null`로 둔다. 수량은 0과 누락을 구분한다. 개방시간은 원문으로 저장하며 현재 개방 여부를 추정하지 않는다.
- HTTP 429/500/502/503/504 또는 네트워크 오류는 1초·2초 간격으로 최대 두 번 재시도한다. HTTP 인증 오류는 재시도하지 않는다. HTTP 200의 JSON 서비스 오류·XML 오류도 실패로 처리한다.

실행별 요약은 `.cache/facilities/import-runs/`의 JSON 파일로 남긴다. 페이지 수·수신/저장/중복/거절/주소 누락 건수, 시작·종료 시각과 고정 오류 코드만 기록한다. 인증키, 요청 URL, 원본 행, 기관 오류 메시지는 기록하지 않는다. 로그는 Git에서 제외된다. 실제 DB 쓰기 후 로그 기록 자체가 실패하면 `LOG_WRITE_ERROR`를 출력하므로 재실행 전 DB 상태를 확인한다.

주요 오류 코드:

- `MISSING_SERVICE_KEY`: 환경 변수 또는 `.env` 설정 확인.
- `HTTP_ERROR`, `API_RESULT_ERROR`, `API_XML_ERROR`: 활용신청 승인, Decoding 키, 계정 쿼터와 서비스 상태 확인. 민감한 전체 응답·URL을 공유하지 않는다.
- `PAGE_METADATA_MISMATCH`, `RESPONSE_SCHEMA_ERROR`: 실제 응답과 문서의 차이를 확인한 뒤 파서를 수정한다.
- `PAGE_COUNT_MISMATCH`, `TOTAL_CHANGED`, `DUPLICATE_RECORD`: 원본 갱신 중일 수 있으므로 잠시 후 전체 재실행. 반복되면 수집 규칙 검토.
- `PAGE_BUDGET_EXCEEDED`: 계정 쿼터를 확인한 후 페이지 예산 조절.
- `STORAGE_ERROR`: DB 스키마·쓰기 권한 확인. 실패 실행의 자료는 반영하지 않는다.

## 5. 검증

```sh
python -m unittest discover -s tests -p test_toilet_import.py -v
```

다중 페이지·재수집·실패 시 기존 자료 유지·중복·지역 불일치·건수 변경·예산 제한·좌표 보존·주소 변경·키 인코딩·오류 응답·재시도를 가상 자료로 검증한다. 2026-11-12 실제 수원시 검증: 코드 `3740000`, 6페이지·588건 수신 및 저장, 중복·거절·주소 누락 각 0건. 도로명주소 검색으로 확인한 558건은 코드 확인용 부분 조회이며, 최종 수집은 지역 코드로 조회한 전체 588건을 사용했다. 좌표는 모두 변환 대기 상태다. 건수는 원본 갱신에 따라 달라질 수 있다.

공식 근거 확인일: 2026-11-11. 원본 서비스의 설명·Swagger 및 [시설 데이터 명세](DATA_SPEC.md)를 기준으로 구현했다.

## 추가 지역 수집 기록 (2026-11-12)

- 안양시: 공식 API 주소 검색에서 지역 코드 `3830000` 확인. 지역 코드 조회 3페이지·258건 검증 및 저장 완료. 중복·거절·주소 누락 0건.
- 군포시: 주소 검색 및 코드 `4020000` 조회 모두 정상 성공 응답이지만 0건. 수집할 행이 없어 DB에 추가하지 않았다. 이 결과는 군포시에 화장실이 없다는 뜻이 아니며, 현 API의 해당 조건에서 제공된 자료가 없다는 의미다. 다른 공식 출처 연계는 별도 검증이 필요하다.
- 로컬 DB: `.cache/facilities/facilities.sqlite3`, 수원 588건과 안양 258건 합계 846건. 기존 수원 자료 보존과 SQLite 무결성을 확인했다. 모든 항목은 좌표 변환 대기 상태다.
- `.cache/`, `*.sqlite*`, `*.db`, `*.db-*` 규칙으로 DB·보조 파일·수집 로그를 커밋에서 제외한다.

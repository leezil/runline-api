# CCTV 수집과 API 신청

구현일: 2026-11-12. 브랜치: `feat/cctv-import`.

## 현재 상태

2026-11-12 CCTV 활용승인 후 기존 인증키로 수원·안양의 전체 목록 검증과 로컬 SQLite 저장을 완료했다. 이전 HTTP 403은 이번 호출에서 재현되지 않았다.

- 수원: 50페이지, 4,934건 저장. 생활방범 3,873건, 방범 외 목적 755건, 미분류(어린이보호) 306건. 불량 좌표 1건.
- 안양: 18페이지, 1,749건 저장. 생활방범 1,114건, 방범 외 목적 409건, 미분류(어린이보호) 226건. 불량 좌표 0건.
- 지역 좌표 분포 추가 검토: 수원 4건·안양 1건의 좌표가 해당 지역 중앙값에서 경도 또는 위도 0.25도 이상 떨어져 검토 대상으로 임시 비활성화했다. 행정경계 판정이나 오류 확정이 아닌 보수적인 수동 검토 조치이며, 원본 좌표는 보존했다. 점검 로그는 `.cache/facilities/cctv-import-runs/regional-review-2026-11-12.json`에 있다. 이 조치는 이번 로컬 DB에만 적용했고 수집기의 일반 자동 규칙으로 추가하지 않았다.
- 최종 지도 조회 가능: 수원 3,870건, 안양 1,113건, 합계 4,983건.
- 기존 화장실 846건 유지, SQLite 무결성 검사 정상. CCTV 원본 보관 총 6,683건. 코드의 좌표 valid는 국내 범위 검사 통과이며 위치 정확성을 보증하지 않는다.


## 신청 방법

1. 공공데이터포털에 로그인하고 [행정안전부_CCTV정보 조회서비스](https://www.data.go.kr/data/15155042/openapi.do)를 연다. Juso와 다른 서비스다.
2. **활용신청**에서 개발계정을 신청한다. 개발 단계에는 화면에서 제공하는 개발/테스트 목적을 선택한다.
3. 활용 설명 예시: `러닝 앱에서 주변 방범 CCTV 설치 위치를 안내하기 위해 공개 설치정보를 수집합니다. 설치목적과 좌표를 검증하여 로컬 SQLite에 저장하고 시설 조회 기능에 사용합니다.`
4. 마이페이지의 오픈API 활용 내역에서 이 서비스의 승인 상태를 확인한다. 승인 방식·처리시간·트래픽 한도는 해당 화면의 안내를 따른다.
5. 승인 상세의 일반 인증키 **Decoding** 값을 로컬 `.env`의 `PUBLIC_DATA_SERVICE_KEY`에 설정한다. 기존 값과 같으면 변경할 필요 없다. 화장실 서비스 승인이 CCTV 사용 승인까지 의미하지는 않는다.

```dotenv
PUBLIC_DATA_SERVICE_KEY=
```

새 변수나 Juso 키는 필요 없다. 환경 변수가 `.env`보다 우선한다. 키를 CLI 인수, 채팅, PR에 넣지 않는다. 기존 `.env`의 키는 구현 중 변경하지 않았다.

목록 API는 `https://apis.data.go.kr/1741000/cctv_info/info`다. 기본 주소 `/cctv_info`에 `/info`를 붙인다. 목록의 목적 필드는 `INSTL_PRPS_SE_NM`이며 이력 API의 `INSTL_PRPS_SE`와 다르다. 이력 API는 이번 구현 대상이 아니다.

공식 포털은 무료, 이용허락범위 제한 없음, WGS84 좌표 제공으로 안내한다. 원본 좌표를 저장하므로 별도 지오코딩을 사용하지 않는다. 일간 갱신·2일 전 기준 현행화 안내와 서버 수집 시각은 구분한다.

## 실행

프로젝트 루트에서 실행한다. 표준 라이브러리만 사용한다.

```powershell
# 승인 후 전체 목록 검증: API는 호출하지만 시설 DB에는 쓰지 않음
python cctv_import.py --region-code 3740000 --dry-run
python cctv_import.py --region-code 3830000 --dry-run

# 검증 결과를 확인한 뒤 저장
python cctv_import.py --region-code 3740000
python cctv_import.py --region-code 3830000
```

수원 `3740000`, 안양 `3830000`이며 군포는 이번 대상에서 제외한다. dry-run도 쿼터를 사용한다. 화장실 지오코딩의 계획 전용 dry-run과 다르다. `--database`, `--env-file`로 로컬 파일을 지정할 수 있다.

`--page-size` 기본/최대 100, `--max-pages` 기본 100/최대 1000이다. 기본 예산은 최대 10,000개 설치 지점의 완전한 목록이다. 초과 시 `PAGE_BUDGET_EXCEEDED`로 종료하며 일부만 저장하지 않는다. 승인된 한도를 확인하고 필요할 때 `--max-pages`를 조정한다. 일시적인 429/5xx/네트워크 오류는 최대 3회 시도하므로 실제 요청 수는 페이지 수보다 많을 수 있다. 403 등 다른 HTTP 오류는 재시도하지 않는다.

403이면 해당 서비스 활용승인, 인증키 종류/값, 승인 후 적용 상태를 확인한다. 계속 실패하면 포털의 해당 서비스 문의 경로를 이용한다. 인증키가 담긴 요청 URL은 첨부하지 않는다.

## 저장과 품질 처리

- `.cache/facilities/facilities.sqlite3`에 기존 화장실과 함께 저장한다. DB와 로그는 Git에서 제외된다.
- 원본·지역·관리번호로 upsert하여 ID를 유지한다. 같은 좌표라도 관리번호가 다르면 별도 시설이다. 카메라 3대인 설치 지점을 3개 마커로 복제하지 않는다.
- 모든 페이지의 총건수·수신 건수·지역·중복을 검사한 뒤 한 트랜잭션으로 저장한다. 실패 시 기존 자료를 보존하며 빈 목록이나 누락 행만으로 삭제하지 않는다.
- 수동 비활성화는 유지한다. 재수집에서 좌표가 사라지거나 잘못되면 이전 정상 좌표를 유지하지 않는다. 목적도 새 응답으로 갱신한다.
- `WGS84_LOT`가 경도, `WGS84_LAT`가 위도다. 유한 숫자이며 경도 124~132, 위도 32~39인 쌍만 `valid/source`로 저장한다. 결측·한쪽 누락·NaN·무한대·0·축 뒤바뀜·범위 밖은 좌표 null, `invalid/none`으로 보관한다. 자동 좌표 교환·지오코딩 대체는 없다.
- 국내 범위 검사는 시 경계 검사가 아니다. 승인 후 지역과 멀리 떨어진 좌표가 없는지 실제 분포를 추가 점검해야 한다.
- 목적/좌표 필드 자체가 응답에서 사라지면 스키마 오류로 중단한다. 필드가 있고 값이 비어 있으면 결측 정책을 적용한다.
- 카메라 대수는 빈 값과 0을 구분한다. 음수·소수·숫자 아닌 값은 배치를 중단한다. 전화번호·촬영방면·화소수는 저장하지 않는다.

## 방범 목적 분류 v1

목적 원문을 보존한다. 구분자 `, ; / + | · ㆍ`와 공백으로 둘러싸인 `및`을 분리하고 앞뒤 공백을 제거한다. 부분 문자열이나 숫자 코드를 추정하지 않는다.

- **true:** 정확한 토큰 `생활방범`이 하나 이상 있을 때.
- **false:** 토큰이 전부 `교통단속`, `교통정보수집`, `쓰레기단속`, `시설물관리`, `재난재해` 안에 있을 때. 앱의 방범 목록에서 제외한다는 뜻이다.
- **null:** 나머지 또는 빈 값. `다목적`, `기타`, `어린이보호`, 숫자 코드, `방범`, `범죄예방`도 추가 확인 전에는 자동 포함하지 않는다.

`생활방범` 의미는 수원시 [범죄예방 CCTV 설치 행정예고](https://paldal.suwon.go.kr/bbsplus/view.asp?bd_gubn=12&code=tbl_bbs_sub200510&dong_gubn=&menuid=&mnuflag=&no=MTIyMzYg&page=41)로 확인했다. 최초 DATA_SPEC의 넓은 후보 사전을 그대로 쓰지 않고 이 항목으로 좁혔다. 실제 두 지역 응답에서 `생활방범`을 확인했다. 미분류 값은 두 지역 모두 `어린이보호`였으며, 이를 자동으로 방범에 포함하지 않았다. 새 목적 값은 공식 설명과 대조하여 사전·테스트를 보완한다. 미확인 값이 많으면 지도에서 제외되는 시설이 많을 수 있다.

저장소의 지도 조회는 active, valid, `crime_prevention=true`인 행만 포함한다. 다른 목적도 저장해야 재수집 시 기존 방범 행의 목적 변경을 반영할 수 있다. 시설의 현재 작동 여부·촬영 범위·안전 점수를 뜻하지 않는다.

## 로그와 검증

`.cache/facilities/cctv-import-runs/*.json`에 지역, 페이지, 수신/저장/오류 건수, 목적 분류 및 결측/불량 좌표 건수를 기록한다. 키, 요청 URL, 원본 응답, 제공자의 오류 메시지는 남기지 않는다. `map_candidates`는 수신 자료 중 목적·좌표 조건을 충족한 수이며 수동 비활성화까지 반영한 DB 조회 건수는 아니다.

```powershell
python -m unittest discover -s tests -p test_cctv_import.py -v
```

가상 응답으로 페이징, 실패 시 기존 자료 보존, 안정적인 ID, 같은 위치의 다른 시설, 목적 변경, 불량 좌표, 비활성 유지, 호출 재시도·키 비노출을 검증했다. 인증된 실데이터 적재·목적 분포·지역 좌표 분포 점검 결과는 위 현재 상태에 기록했다. 임시 비활성화한 5건의 정확한 위치 확인은 남아 있다.

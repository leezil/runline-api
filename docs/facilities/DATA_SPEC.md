# 공중화장실·방범카메라 데이터 연동 명세

확인일: 2026-11-11 (한국 시간). 상태: 수집·저장 구현을 위한 설계이며 아직 시설 API는 구현되지 않았다.

구현 상태: 내부 시설 저장소는 [저장소 사용법](STORAGE.md)을 참고한다. 아래 수집·HTTP API 관련 내용은 후속 구현 계약이다.

화장실 목록 수집기는 [수집·키 설정 안내](TOILET_IMPORT.md)에 구현 범위와 실행법을 정리했다. 2026-11-12 인증 호출과 수원시 588건 저장을 검증했다. 지오코딩과 갱신·삭제 동기화는 아직 수행하지 않았다. 아래 2026-11-11 조사 기록의 미검증 상태와 구분한다.

## 1. 범위와 결정

서버가 공공데이터를 배치 수집하고 별도 시설 DB에 저장한다. 앱의 지도 요청에서는 이 DB만 조회하며 공공데이터 API 호출이나 주소 좌표 변환을 수행하지 않는다. 도로 DB와 경로 계산 엔진은 변경하지 않는다.

- 화장실: 행정안전부 공중화장실정보 조회서비스의 **v2**를 1차 출처로 사용한다. 현재 좌표를 제공하지 않으므로 주소 변환을 별도 단계로 둔다.
- CCTV: 행정안전부 CCTV정보 조회서비스에서 방범 목적이 확인된 설치 지점을 수집한다. 원본 WGS84 좌표를 우선 사용한다.
- 전국 수집을 목표로 하되 첫 검증은 수원시로 제한한다. 개방자치단체코드는 공식 코드 파일에서 확인하며 추정하지 않는다.
- 실제 DB·원본 응답·수집 로그는 `.cache/facilities/`에 두고 Git에 올리지 않는다. 테스트에는 직접 만든 가상 자료만 사용한다.
- 영상, 실시간 작동 상태, 범죄 위험도, 현재 화장실 개방 여부는 이번 기능의 제공 대상이 아니다.

## 2. 공식 출처와 접근 방식

### 화장실

[행정안전부 공중화장실정보 조회서비스](https://www.data.go.kr/data/15155058/openapi.do)의 상세 설명과 페이지 내 Swagger를 확인했다.

- 목록: `https://apis.data.go.kr/1741000/public_restroom_info_v2/info_v2`
- 이력: `https://apis.data.go.kr/1741000/public_restroom_info_v2/history_v2`
- JSON/XML 제공. 무료, 이용허락범위 제한 없음으로 안내한다.
- 일간 갱신이며 상세기능 설명에는 2일 전 기준 현행화라고 기재되어 있다. 수집 시각이 원본의 최신성을 뜻하지 않는다.
- 2025년 2월 원천 정책 변경으로 WGS84 위도·경도 제공이 중단되었다. 과거 자료나 검색 요약의 좌표 제공 설명을 현재 계약으로 사용하지 않는다.

[전국공중화장실표준데이터](https://www.data.go.kr/data/15012892/standard.do)는 CSV 대안 출처다. 최초 구현은 API로 통일하며 CSV를 병행 수집해 중복을 만들지 않는다.

### CCTV

[행정안전부 CCTV정보 조회서비스](https://www.data.go.kr/data/15155042/openapi.do)의 상세 설명과 페이지 내 Swagger를 확인했다.

- 목록: `https://apis.data.go.kr/1741000/cctv_info/info`
- 이력: `https://apis.data.go.kr/1741000/cctv_info/history`
- JSON/XML, WGS84 좌표 제공. 무료, 이용허락범위 제한 없음으로 안내한다.
- 일간 갱신이며 상세기능 설명에는 2일 전 기준 현행화라고 기재되어 있다.
- 개발계정 신청 가능 트래픽은 페이지에 10,000으로 표시되어 있다. 실제 승인 계정의 적용 단위·잔여량을 확인해 수집 예산을 설정한다.

[전국CCTV표준데이터](https://www.data.go.kr/data/15013094/standard.do)는 CSV 대안 출처다. 한 행에 여러 카메라 대수가 있을 수 있으므로 설치 지점 수와 카메라 수를 구분한다.

### 인증·페이지 처리

두 서비스 모두 활용신청 후 `serviceKey`가 필요하다. 서버 전용 환경 변수 이름은 후속 구현에서 `PUBLIC_DATA_SERVICE_KEY`로 사용한다. 현재 서버가 이 변수를 읽는다는 뜻은 아니다. 키를 앱, 요청 샘플, PR, URL 로그에 포함하지 않는다. HTTP 라이브러리에서 쿼리를 한 번만 인코딩한다.

공식 요청 항목은 `serviceKey`, `pageNo`, `numOfRows`(최대 100), `returnType`이다. 목록에는 `cond[OPN_ATMY_GRP_CD::EQ]`, `cond[DAT_UPDT_PNT::GTE]`, `cond[DAT_UPDT_PNT::LT]` 등을 사용할 수 있다. 날짜 경계의 원본 표현은 `YYYYMMDDHHMMSS`다.

공식 Swagger의 응답 경로는 `response.header.resultCode`, `response.header.resultMsg`, `response.body.totalCount`, `response.body.items.item`이다. HTTP 200만으로 성공 처리하지 않는다. 성공 코드·빈 결과 형태·단일 항목 표현은 인증 호출로 확인한 뒤 어댑터 테스트에 고정한다. 오류 응답이 XML인 경우도 판별한다.

인증 호출은 이번 작업에서 하지 않았다. 포털의 인증 없는 샘플 링크는 두 서비스 모두 HTTP 403을 반환했다. 따라서 **문서·Swagger 확인 완료 / 실제 데이터 호출 미검증** 상태다.

## 3. 공통 저장 필드와 원본 매핑

아래 영문 원본 필드명은 현재 목록 조회 Swagger 기준이다. 이력 응답을 같은 스키마로 가정하지 않는다. 예를 들어 CCTV 설치 목적은 목록의 `INSTL_PRPS_SE_NM`과 이력의 `INSTL_PRPS_SE`가 다르다.

- `id`: Runline 내부의 안정적인 불투명 문자열 ID. 주소나 이름 변경으로 바뀌지 않는다.
- `kind`: `toilet` 또는 `cctv`.
- `source`: `mois_toilet_v2` 또는 `mois_cctv`.
- `source_region_code` ← `OPN_ATMY_GRP_CD`.
- `source_record_id` ← `MNG_NO`. `(source, source_region_code, source_record_id)`를 유일 키로 사용한다. 식별자가 없는 행은 격리하고 주소 해시로 임의 대체하지 않는다.
- `address_road` ← `LCTN_ROAD_NM_ADDR`, `address_lot` ← `LCTN_LOTNO_ADDR`. 빈 문자열은 `null`로 정규화한다.
- `manager_name` ← `MNG_INST_NM`.
- `source_date` ← `DAT_CRTR_YMD`, `source_modified_at` ← `LAST_MDFCN_PNT`, `source_updated_at` ← `DAT_UPDT_PNT`.
- `source_change_type` ← `DAT_UPDT_SE`. 코드 의미는 공식 코드 자료와 실제 응답으로 확인하기 전까지 원문으로 보존한다. 삭제 코드를 추정하지 않는다.
- `fetched_at`: 서버 수집 시각, UTC ISO 8601. 원본 날짜·시간은 별도로 보존하고 원본 시간대가 확인되기 전 UTC로 임의 해석하지 않는다.
- `longitude`, `latitude`: WGS84 숫자 또는 `null`. 둘 중 하나만 있는 좌표는 유효하지 않다.
- `coordinate_source`: `source`, `geocoder`, `none`. 변환 시 제공자·변환 시각·주소 해시를 별도로 저장한다.
- `coordinate_status`: `valid`, `pending`, `ambiguous`, `invalid`, `failed`.
- `active`: 원본의 삭제·전체 스냅샷 검증 정책에 따른 상태. 현재 영업·작동 여부를 뜻하지 않는다.

같은 좌표나 주소라도 다른 시설일 수 있다. 식별자 기준 중복만 병합하고, 서로 다른 ID의 근접 시설은 보존한다. 원본 숫자 항목은 문자열로 선언되어 있으므로 빈 값과 0을 구분하고 유효한 비음수 정수만 변환한다.

### 화장실 추가 필드

- `name` ← `RSTRM_NM`, `category_raw` ← `SE_NM`.
- `opening_hours_text` ← `OPN_HR`, `opening_hours_detail` ← `OPN_HR_DTL`. 원문 안내로 제공하며 불완전한 문구에서 `open_now`를 추정하지 않는다.
- 남성 대변기·소변기 수 ← `MALE_TOILT_CNT`, `MALE_URNL_CNT`.
- 여성 대변기 수 ← `FEMALE_TOILT_CNT`.
- 장애인용 변기 수 ← `MALE_FRDBL_TOILT_CNT`, `MALE_FRDBL_URNL_CNT`, `FEMALE_FRDBL_TOILT_CNT`. 변기 수만으로 건물 전체의 휠체어 접근성을 판정하지 않는다.
- 비상벨·기저귀교환대 ← `EMRGNCBLL_INSTL_YN`, `DIAP_EXCHCON_EN`. 원본 허용값을 확인한 후 `true/false/null`로 변환한다.
- 좌표는 현재 v2 응답에 없다. 최초 저장은 `pending`이며 지도에 표시하지 않는다.

전화번호·촬영방면·보관일수 등 앱 목적에 필요하지 않은 항목은 공개 응답에서 제외한다.

### CCTV 추가 필드와 방범 판정

- `purpose_raw` ← `INSTL_PRPS_SE_NM`, `camera_count` ← `CAM_CNTOM`.
- `latitude` ← `WGS84_LAT`, `longitude` ← `WGS84_LOT`. `LOT` 표기를 임의로 `LON`으로 바꾸지 않는다.
- 별도 시설명이 없으므로 `name`은 표시용으로 `방범 CCTV`를 사용하고 주소를 상세 정보로 제공한다.
- 원본 목적을 보존하고 공백 정리·명시적 구분자 분리 후 승인된 목적 사전으로 분류한다.
- 초기 포함 후보는 `생활방범`, `방범`, `범죄예방`, `어린이보호`다. **실제 관측 값·공식 목적 정의를 확인하여 매핑을 확정하기 전에는 후보 문자열을 그대로 운영 허용 목록으로 사용하지 않는다.**
- `교통단속`, `교통정보수집`, `쓰레기단속`, `시설물관리`, `재난재해`만 있는 항목은 방범 목록에서 제외한다. 위 표기는 프로젝트 분류 예시이지 확인된 전체 원본 코드 목록이 아니다.
- `다목적`, `기타`, 빈 값은 그 자체로 방범이라고 추정하지 않고 검토 대상으로 둔다. 복수 목적 중 확인된 방범 목적이 있으면 포함하되 전체 목적을 보존한다.
- 카메라 3대인 한 설치 지점을 3개 마커로 늘리지 않는다. CCTV 위치에서 촬영 범위나 안전 점수를 계산하지 않는다.

## 4. 좌표 검사와 주소 변환

현재 경로 서비스와 일관되게 124 ≤ 경도 ≤ 132, 32 ≤ 위도 ≤ 39 범위를 1차 검사한다. 이는 한국 육지 경계 판정이 아니다. NaN, 무한대, 0·0, 누락, 뒤바뀐 좌표는 격리하고 자동 교환하지 않는다. 수원시 시범 수집에서는 지역과 동떨어진 좌표도 별도 점검한다.

화장실은 도로명 주소 우선, 없으면 지번 주소를 사용한다. 같은 정규화 주소의 재사용 키에는 제공자와 변환 규칙 버전을 포함한다. 원본 주소가 바뀌면 기존 좌표를 무효화한다. 지역 불일치·복수의 불명확한 후보는 `ambiguous`로 남긴다. 실패를 임의 좌표나 지역 중심점으로 채우지 않는다. CCTV의 불량 좌표는 최초 버전에서 격리하며 주소 변환으로 조용히 대체하지 않는다.

### 변환 제공자 결정 상태

[카카오 주소 검색 문서](https://developers.kakao.com/docs/ko/local/dev-guide)는 서버 REST API와 REST API 키 인증을 설명한다. 기존 지도용 JavaScript 키와 구분해야 한다. 그러나 API 호출 가능 여부와 결과 장기 저장 허용은 별개다.

[카카오 운영정책](https://developers.kakao.com/terms/ko/site-policies) 제5조의 캐시·데이터 사용 제한 및 [공식 데브톡의 캐시 안내](https://devtalk.kakao.com/t/api/140197)를 확인했다. 이 근거로 카카오 결과를 전국 시설 DB에 영구 저장해도 된다고 판단하지 않는다.

결정: `feat/toilet-geocoding`에서 장기 저장·앱 재제공이 허용되는 제공자 또는 별도 승낙을 확인하고, 사용량·비용·출처 표시·보존 기간을 문서화한 뒤 실제 변환을 활성화한다. 현재 제공자는 미정이다. 좌표 없는 원본의 수집·저장과 CCTV 구현은 이 결정과 독립적으로 진행할 수 있다.

## 5. 수집·갱신 설계

프로젝트 운영 목표는 일 1회 갱신이다. 원본 기관의 갱신 보장과 구분한다. 처음에는 수동 실행으로 검증하며 스케줄은 별도 브랜치에서 추가한다.

1. 수집 시작 시 원본·지역·범위·시작 시각을 기록하고 임시 저장소에 적재한다.
2. 페이지 1부터 끝까지 처리하고 총건수·수신건수·중복·불량좌표·누락필드·목적 미분류 건수를 기록한다.
3. 페이지 실패, 인증 오류, 스키마 변경, 총건수 불일치가 있으면 해당 실행을 실패 처리한다. 부분 결과를 정상 스냅샷으로 교체하지 않는다.
4. 검증된 스냅샷만 트랜잭션으로 반영하고 성공 시각을 갱신한다. 기존 정상 데이터는 실패 시 유지한다.
5. 후속 증분 수집은 원본 갱신시점으로 겹치는 시간 구간을 재조회하고 유일 키로 upsert한다. 모든 페이지가 성공하기 전 체크포인트를 전진시키지 않는다.
6. 삭제 코드의 의미가 확인되면 명시적 삭제를 처리한다. 전체 비교에 의한 비활성화는 같은 지역의 완전한 스냅샷이 확보된 경우에만 수행한다. 목적 변경·좌표 무효화도 조회 노출에 반영한다.

429·일시 오류에는 제한된 지수 백오프를 사용하고 인증 오류에는 반복 재시도하지 않는다. 실제 키·쿼터가 준비되면 초기 페이지 수와 호출 예산을 계산한다. 계정 쿼터나 좌표 변환 비용을 상수로 가정하지 않는다.

## 6. 앱 연동 계약 초안

다음은 `feat/places-api`에서 구현할 계약 초안이다. 현재 `GET /v1/places`는 제공되지 않는다.

- 요청: `GET /v1/places?types=toilet,cctv&west=127.00&south=37.27&east=127.02&north=37.29`.
- `types`는 생략 시 두 종류, 지정 시 알려진 값만 허용한다. 경계 4개는 필수 유한 숫자이며 `west < east`, `south < north`와 국내 범위를 검사한다.
- 제안 제한: 가로·세로 각각 10km 이하, `limit` 기본 200·최대 500. 경계 초과는 400. 실제 부하 측정 후 API 구현 PR에서 확정한다.
- `active`이고 좌표가 유효한 항목만 반환한다. CCTV는 확인된 방범 목적만 포함한다.
- 응답 초안: `items`, `count`, `truncated`, `data_updated_at`, `sources`. 정렬은 `id` 기준으로 안정화한다. `limit + 1` 조회로 초과를 판별한다. `truncated: true`일 때 클라이언트는 지도 확대를 안내하며 전체 시설을 받았다고 표시하지 않는다.
- 항목 공통 필드: `id`, `type`, `name`, `location`([경도, 위도]), `address`, `source`, `source_date`, `coordinate_source`. 화장실에는 개방시간 안내, CCTV에는 설치 목적과 대수를 추가한다. 미제공 값은 `null`이다.
- `data_updated_at`은 조회한 시설 종류별 마지막 정상 적재 시각이다. 시설별 `source_date`와 구분한다.
- 정상 적재된 빈 지역은 200과 빈 배열이다. 요청한 종류 중 하나라도 최초 적재가 없으면 503으로 구분한다. 수집 실패 후 기존 자료를 제공할 때는 종류별 갱신 실패 상태를 명시한다.
- 외부 포트는 기존 테스트 API의 Bearer 인증 방식을 유지하는 방향으로 구현한다. 공공데이터·지오코더 키는 서버에만 둔다. 배포 앱에 공유 테스트 토큰을 내장하는 방식을 운영 인증으로 확정하지 않는다.
- 클라이언트 담당: 지도 이동 후 호출 간격 조절, 오래된 응답 무시, 토글·마커·상세 표시·출처 표시. 서버 담당: 적재·조회·오류·인증·최신성 명세와 샘플 제공.

## 7. 다음 브랜치의 완료 기준

- `feat/facility-storage`: 위 공통 모델과 유일 키, 위치 인덱스, 좌표 없는 행의 보존, 트랜잭션·가상 자료 테스트. 실제 키 없이 진행 가능하다.
- `feat/toilet-import`: 활용신청·코드 파일 확인, v2 인증 호출, 실제 응답·오류·페이지 완료 검증, 수원시 시범 적재. 주소 좌표 변환은 하지 않는다.
- `feat/toilet-geocoding`: 제공자 저장 조건 확인 후 변환·실패 분류·주소 변경 무효화. 조건 미확정이면 실제 대량 변환을 켜지 않는다.
- `feat/cctv-import`: 설치목적 관측 값과 공식 정의를 대조해 목적 사전 확정, 좌표 품질·동일 좌표 별도 시설·복수 카메라 처리 검증.
- `feat/places-api`: 조회 범위·좌표 순서·인증·빈 결과·미적재·잘림·최신성 테스트와 클라이언트용 샘플.
- `feat/facility-refresh`, `chore/facility-refresh-schedule`: 실패 중 기존 자료 유지, 증분 체크포인트·삭제 의미 검증 후 정기 실행.

## 8. 이번 작업의 검증 기록

- 공식 포털 설명과 내장 Swagger에서 URL·필드·페이지 한도·좌표 제공 변경을 확인했다.
- 인증 없는 공식 샘플은 HTTP 403으로 확인되어 실제 행 값과 인증 성공을 검증했다고 주장하지 않는다.
- 문서 내 상대 링크, 필드명, 코드 변경 여부와 민감정보 포함 여부를 확인한다.
- 실행 코드·패키지·DB를 변경하지 않으므로 이번 문서 커밋에서는 런타임 테스트를 반복하지 않는다.
